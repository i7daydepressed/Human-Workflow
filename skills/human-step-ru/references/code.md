# Программные правки и текст коммита

Прочитать фактические репозиторий, ветку, полный SHA, diff и index. Коммиты сравнивать в реальном порядке. Для правки указать файл/класс/метод, проверенную строку или диапазон, однозначный якорь, вставку до/после/замену, достаточный старый и полный новый блок. Назвать границы удаления и сохраняемый код; новый файл дать целиком. После вставок предпочитать проверенные якоря устаревшим номерам строк. Не заменять нужную реализацию многоточием.

Проверить уникальность якоря в указанной области, зависимости вставок и общую точку сборки. Исторический снимок не является прочитанным текущим diff. Новая база и частичный патч не разрешают откат. Сохранять принятые границы UI/состояния/обработки; новую архитектуру выводить из текущих решений, а не образца.

Объяснять реальные входы, вызовы, изменение состояния и получение результата пользователем. Аналогию с другим языком давать, когда она помогает адресату. Язык комментариев, типографику, явные/выводимые типы и скобки брать из правил репозитория и выбранного профиля; личные настройки автора не навязывать. Сохранять комментарии пользователя, исправлять неточности предметно. Объяснять неочевидные ограничения/математику/данные вместо очевидных свойств. Для существенных расчетов дать формулу, нужные промежуточные величины и независимый малый пример. Точные утверждения о внутренностях библиотеки проверять по первичной документации/реализации.

Перед ревью прочитать реальный diff и связанные файлы. Запрос ревью не разрешает исправлять все находки. Различать сборку, сервисный/headless-запуск, расчет, нативный GUI и наблюдения человека. Минимальную адаптацию API описывать с основанием; весь проект автоматически не модернизировать.

Для запрошенного текста коммита использовать язык и согласованный формат проекта. Называть реальные механизмы: `Class.Method()` получает X, вызывает Y, обновляет Z. Не писать неподтвержденное «архитектура улучшена». Если основание — подтвержденный пользователем пакет, а не diff, указать это вне копируемого текста. Сохранить существенные ограничения; убрать историю обсуждения и обещания. Запрос сообщения не разрешает commit/push. Завершать проверками/предложенным текстом, если исполнение не поручено. См. [примеры сообщений](commit-examples.md) и [адаптированный пакет](packet-example.md); их код и прошлые наблюдения не описывают текущую задачу.
