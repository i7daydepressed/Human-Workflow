# Содержание и доказательства

Составить карту «требование → результат ядра/ответ → проверка → раздел/материал объяснения». Если итоговый отчет не входит в поручение, сохранять только нужное состояние и объяснение, без искусственного оглавления. Не делать отдельный формальный раздел для каждого предложения методички, если это создает повтор введения. Введение должно объяснять цель, предмет и конкретный результат работы; заключение – что достигнуто и на чем это видно. Не опускать введение потому, что есть «постановка задачи».

Сначала показать читателю общий процесс, затем вводить модель, ее поля и отдельные методы. Ссылаться на реальные полные имена методов и pinned commit. Различать обозначение `Класс.Метод()` для поиска исходника и фактический вызов метода экземпляра. Не объявлять метод статическим только из-за такой записи.

Теорию связывать с практикой примерами, но не смешивать смысл структурного элемента с весами фильтра и не обобщать частный алгоритм на все библиотеки. Если вычисляет библиотека, показать подготовку/вызов и проверенный источник ее поведения. Сохранять выбранные единицы, соглашения о каналах, краях, опоре и отражении.

Не включать все разработческие заметки, оборудование, историю захвата, отладочный вывод и пошаговую инструкцию запуска в основной учебный текст без необходимости. Хранить воспроизводимость в sources, capture-notes, word-conversion и логе. Для запроса на сокращение сначала убрать повторы и лишнюю историю, сохранив требования, результаты, ключевые методы, ошибки и доказательства. Создать отдельную short-редакцию, пока пользователь не выбрал ее основной.

Различать: исходник прочитан; сборка выполнена; численный пример рассчитан; GUI действительно запущен; пользователь подтвердил поведение; преподаватель принял работу. Сохранять обнаруженные ограничения даже после успешной сдачи. Сдача не означает автоматического исправления дефекта.

Для каждой иллюстрации дать смысл перед ней и разбор после. Короткий вывод должен объяснять конкретный пример, затем применение. Избегать одинакового вводного слова в каждом абзаце. Если пользователь просит абзацы по операциям, начинать их с жирного названия, но не навязывать этот прием всем разделам.

В таблицах знаний сверять полные наборы/числа с исходными данными. Называть источник каждого факта или диапазона. Рабочий план реализации не считать доказательством текущего кода. При противоречии актуального файла и памяти брать файл, сохраняя пользовательские исправления.

Теоретические вопросы, дополнительные файлы и демонстрации брать из текущего задания. ТЗ и пакеты описывают намерение; фактическую реализацию подтверждают версии артефактов и проверки. При изменении ядра определить затронутые утверждения/рисунки, обновить их или явно оставить привязку к прежней версии.

Для запроса о результатах исполнения составить покрытие «пункт → действие/запрос → фактический результат → доказательство → ограничение». Счетчик строк и видимый фрагмент таблицы различать. Сообщение PREPARE не подтверждает выполнение EXECUTE; результат отдельной расчетной среды не называть снимком целевого приложения. Если обязательного кадра нет, отметить его отсутствие и получить/воспроизвести в доступных пределах, не маскируя расчетной таблицей.

Для внешних фактов, правил и диапазонов указывать источники; авторскую формализацию отделять от утверждения эксперта. Индивидуальный язык/пунктуацию и оформление брать из профиля проекта, см. user-profile.md.

## Показать выбранное содержание

При поэтапной работе MD → Word показать актуальный Markdown либо доступную ссылку, обозначить редакцию/хеш и сохранить ожидание согласования в существующем состоянии до конвертации. Использовать одобрение выбранной редакции; для явной прямой конвертации или пропуска записать источник решения, не выдумывая одобрение. Существенные изменения отменяют относящееся к ним одобрение. Для изменения байтов без существенного изменения содержания записать проверенную эквивалентность и связь редакций. Правки только оформления авторитетного DOCX сохраняют это решение, пока требования или содержание не меняются. См. [контракт MD_APPROVAL](../workflow.md).
