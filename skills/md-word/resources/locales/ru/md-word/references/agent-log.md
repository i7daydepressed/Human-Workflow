# Журнал агента и продолжение

Использовать применимый AGENTS.md и существующий формат журнала/атрибуции. Иначе вести `agent-logs/<run-id>.md`, один владелец записи исполнителя. При передаче сослаться на предшественника и начать запись нового исполнителя; достаточный общий журнал не дублировать. Рабочие журналы не включать в сдаваемый отчет.

Записать приложение/роль/ID автора, модель и источник/точность идентичности, задачу/пользователя, действительно прочитанную редакцию/версию инструкций, наблюдаемое время начала и часовой пояс. Неизвестность допустима. Название семейства в UI или собственная метка не являются точным API model ID. Известное имя пользователя использовать только при нужде; не собирать личные сведения ради журнала.

После значимых пакетов фиксировать цель, реальные действия, файлы/ID/версии, наблюдения, проверки/ограничения, решения и следующий шаг. Исключать учетные секреты, лишние личные данные, скрытые рассуждения и полные диалоги. Сохранять буквальные цитаты/команды и один язык журнала независимо от языка инструкций. Восстановленные записи помечать ретроспективными с источником. Время/токены приводить только при измерении.

Необязательный локальный помощник: заполнить identity.json полями `agent`, `agent_id`, `id_source`, `model`, `model_source`, `user`, `task`, `skill_version`, `timezone`; отсутствующую идентичность явно отметить неизвестной. Запустить `agent_journal.py start <project> --identity identity.json` из shared/scripts, сохранить возвращенные run ID/path, затем использовать `append <project> --run-id RUN --entry entry.json`. У записи поля `goal`, `actions`, `files`, `checks`, `result`, `user_decision`, `next_step`. Помощник локален, синхронизацию не выполняет. Создаваемый текст поддерживает RU/EN; часть ошибок остается русской.

Возобновлять по текущему состоянию/нужным последним записям, а не всему архиву. В кратком состоянии обновлять версии/приемку/расхождение/журнал/снимок/следующий шаг; историю оставлять в журнале. Автора пакета, исполнителя, автора объяснения и проверяющего указывать по свидетельствам. Позднее обновление скила не меняет ранее записанную версию. Состояние/журнал сохранять обычным способом с проверкой каждой записи. При сбое синхронизации сохранить локальное и указать незавершенное сохранение. Разделять самоотзыв, ответ пользователя и приемку.
