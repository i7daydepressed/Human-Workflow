# Миграция идентичности и возврат

[English](migration.en.md). Цель — `human-workflow` `0.0.7`, отображение Human-workflow-v0.0.7, Apache-2.0. Скилы `human-step`/`md-word`, каталог репозитория `workflow-tools`, схема профиля 1 и i02-идентификаторы Word-пресетов сохраняются. Это инструкция для будущей явно разрешённой миграции; подготовка кандидата не меняет реальную установку, кеш, профиль или аккаунт.

## Установить фактическое состояние

Записать клиент/приложение и версию, известный способ аутентификации, регистрацию каталога, установленные имя/версию/путь плагина, включённость и пакет для возврата. HEAD исходников не определяет установленную версию. До смены регистрации получить хеши только явно выбранных внешних профилей/задач/личных Word-ресурсов; сохранить их байты и более новую работу. Не искать профили и не сканировать историю аккаунта.

## Claude Code

Каталог Claude содержит дополняемое соответствие `workflow-tools-preview` → `human-workflow`. Не переписывать и не удалять историю переименований. [Официальная документация](https://code.claude.com/docs/en/plugins/host-marketplace#rename-or-remove-a-plugin) описывает ключи настроек; управляемые настройки могут потребовать правки администратора. Для Git/URL-каталогов может понадобиться один явный `claude plugin install human-workflow@workflow-tools`, чтобы заполнить новый кеш.

При доступном CLI проверить каталог/манифест кандидата командой `claude plugin validate .` и записать фактический вывод/версию; иначе отметить проверку как not run. После будущей разрешённой установки проверить свежий контекст. Само соответствие не является результатом миграции. Поведение CLI не подтверждает Claude chat или синхронизацию аккаунта.

## Codex и другие среды

Автоматический аналог переименования не подтверждён. Через поддерживаемое управление плагинами описать прежнюю регистрацию, сохранить пакет для возврата, подготовить кандидат, по ситуации отключить/удалить прежнюю активную идентичность, установить новую и проверить свежий контекст. [Документированные команды CLI](https://learn.chatgpt.com/docs/developer-commands) включают `codex plugin list --json`, `codex plugin remove <plugin@marketplace> --json` и `codex plugin add human-workflow@workflow-tools --json`. Использовать фактически обнаруженное старое имя; эти команды не разрешено запускать только из-за наличия в инструкции.

Отдельный прежний каталог `workflow-preview-i04` обрабатывать лишь при его реальном наличии. Не переименовывать/удалять все каталоги, не удалять кеши вручную и не сохранять дубликаты активного координатора как способ миграции. Сохранять посторонние расширения и регистрации.

## Проверить и вернуть прежнюю версию

В свежем контексте наблюдать новую установленную идентичность/версию/пути workflow/ресурсов и отсутствие дубликата прежнего активного координатора. Повторно проверить выбранные хеши внешних данных и осмотреть намеренные изменения. Отделять выбор/загрузку от успеха вычислений, помощника или артефакта. Недоступные клиентские, поведенческие и миграционные проверки отмечать not run.

Возврат восстанавливает выбранную прежнюю регистрацию/пакет поддерживаемым способом. Он не перезаписывает более новые состояния задач, внешние профили или личные Word-ресурсы. Сохранить запись фактических действий, результатов и исполнителя. Лицензия старого выпуска остаётся исторической; Apache-кандидат её не переписывает.
