# Specification, handoff, and report accompaniment

## Shared basis

Use the existing task/specification and concise current state. A link and a few working-note points suffice for small tasks. Do not create a tracking system for every packet or restructure suitable folders.

Map requirement → step → actual result → check. Keep requirement and implementation versions separate. A full SHA is not a specification revision; a step number is not execution evidence. Without a specification, use the actual assignment and identify the basis and necessary gaps.

| Requirement and source/revision | Packet/step | Result and version | Check/limit |
| --- | --- | --- | --- |
| Actual clause | Identifier | Path/ID and commit/revision | Actual status or planned check |

## Participants

The main agent/person owns the task, agreed decisions, packet preparation, and returned-result review. An executor performs bounded steps and returns observed facts. Roles may be combined; separate models or skill installations are unnecessary.

Author and executor modes share this contract. Treat old precise-code-workflow references as the predecessor process, without carrying over outdated sources. At a new start, name the current skill and role if the recipient does not know them.

If the main agent uses md-word otchet workflow, give the executor the necessary requirements, scope, and report evidence to return. Do not make a bounded code executor read the whole report skill. Prefer the English companion when available; otherwise use the active edition and do not load both for the same task.

## Minimum handoff

Provide:

- Purpose, current task/specification, relevant clauses.
- Packet revision, starting object/version, dependencies.
- Exact actions and limits of independent adaptation.
- Verification criteria and required evidence.
- Return path/method and known limits.

Return actual changes, versions, step statuses, checks, and remaining actions. A person's concise answer, photo, or task file may suffice; do not demand Git/technical JSON without a need.

Files above the working folder are not automatically known to an agent. Put accessible paths/links in project instructions. Across machines/services, verify accessibility instead of assuming a shared filesystem.

## Explanation/report materials

Preserve concise reasons for significant decisions, data transformations, results, and illustration provenance. Do not request hidden chain-of-thought or the complete conversation.

If the assignment requires work history, arrange evidence capture before hard-to-repeat actions. Without history, distinguish facts established from current files, a new run, executor reports, and unrecoverable history.

After handoff, update current state and leave history in the log. For a new chat, provide current requirements, versions, completed work, checks, open issues, and next step. Context exhaustion does not end the task.

A full report, Word, and specific formatting require the corresponding assignment and specialist skill. Accompaniment without a mandatory final report remains valid.
