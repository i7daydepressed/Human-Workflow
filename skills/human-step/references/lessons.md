# Adapted historical observations

These summaries derive from observations recorded in earlier workflow documentation. Detailed private logs/commits are not bundled; historical runs were not repeated for this candidate. They are not current execution facts or proof of this version's effectiveness.

| Recorded situation | Transferable action | Limit |
| --- | --- | --- |
| A packet followed local uncommitted work absent from the remote base | Inspect actual methods and preserve earlier changes | A clean tree is not mandatory; do not roll back to an old SHA |
| An installed API needed a nullable generic adjustment | Make the minimal verified adaptation and return its reason/check | Do not replace all similar types across versions |
| Calculation/build/headless checks succeeded while native control timed out; a later entry reported a GUI run | Name evidence type, version and executor | A later report is not this agent's new GUI action |
| Build-material relocation followed earlier tests | Retain prior coverage with its version; recheck affected behavior | Old success is not a new run after relocation |
| A later UI packet remained pending after an archive move | Keep prepared/executed/accepted states separate | Filename/location is not execution |
| A crash was reproduced on a baseline despite another passing group | Preserve failure, provenance and a separate next step | Passing checks do not close unrelated defects |
| Auxiliary test/build projects entered main processing inputs | Locate harnesses intentionally; change build rules only when assigned | No universal exclusion edit follows |
| Comment edits needed explanation and executable-code preservation | Explain data flow and non-obvious constraints; check proportionately | A calculation/comment check is not a GUI run |
| Manual/non-code scope was later added | Use confirmed object/action/observation contracts | A new instruction does not prove a hardware trial |
