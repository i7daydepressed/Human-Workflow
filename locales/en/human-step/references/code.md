# Programming edits and commit text

Read the actual repository, branch, full SHA, diff and index. Compare commits in their real order. For each edit identify file/class/method, verified line or range, unique anchor, before/after/replace placement, enough old text and the complete replacement. State deletion boundaries and retained code; give a new file in full. After insertion prefer checked anchors over stale line numbers. Never hide required executable code behind ellipses.

Verify anchor uniqueness in the stated scope, insertion dependencies and the combined build point. A historical snapshot is not an inspected current diff. A newer base or partial patch does not authorize rollback. Preserve accepted UI/state/processing responsibilities; derive new architecture from current decisions, not an example.

Explain actual inputs, calls, changed state and how output reaches the user. Use a language analogy only when helpful to the recipient. Follow repository rules and the selected profile for comment language, typography, explicit/inferred types and braces; impose no author's private defaults. Preserve user comments, correcting inaccuracies specifically. Explain non-obvious constraints/math/data boundaries rather than obvious properties. For material calculations provide formula, needed intermediate values and an independent small example. Verify precise library-internal claims against primary documentation/implementation.

Inspect the real diff and related files before reviewing a commit. A review request does not authorize fixing every finding. Distinguish build, service/headless run, calculation, native GUI and human observations. Describe any minimal API adaptation and its evidence; do not modernize the whole project automatically.

For requested commit text use the repository/project language and an agreed format. Name actual mechanisms such as `Class.Method()` receiving X, calling Y and updating Z. Avoid unsupported “architecture improved”. If based on a user-confirmed packet rather than a diff, say so outside the copyable text. Keep material limits; omit conversational history and promises. Requesting a message does not authorize commit/push. End with checks/proposed text unless execution was authorized. See [message examples](commit-examples.md) and the [adapted packet](packet-example.md); their code and past observations do not describe the current task.
