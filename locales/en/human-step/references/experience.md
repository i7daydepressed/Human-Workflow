# State, log and experience

Use existing project state/log rules, including applicable AGENTS.md. Keep current requirements/versions/completed work/limits/next step in concise state; preserve significant actions and decisions in the log. Without a shared log use a distinct executor file. Do not overwrite other agents' records or create duplicate template-named files.

Record task, author/role, instruction version/edition actually read, known model/ID and the source of that identity; unknown is valid. A self-chosen label is not system identity. Do not require a human model questionnaire. Record an event once in the chosen log language, independently of instruction language; retain literal commands/quotes/IDs. A later skill update does not change which version was read earlier.

After a significant packet record request, decision, actual actions, files/versions, checks/limits, user decisions and next step. Keep current status current while preserving old failed/not-run observations historically. Exclude secrets, unnecessary personal data, hidden reasoning and full chat transcripts. Mark reconstructed entries retrospective and identify their source.

Save proportionate feedback using the optional form or existing project format; preserve others' entries and check synchronization. Separate observation, suspected cause, correction, outcome and proposal; include successful methods too. Report time/tokens only when measured. Agent self-review, user assessment and acceptance are distinct.

During an authorized development task trace evidence → rule/change → verification. Distinguish missing/ignored rules, tool failures, environment limits and project requirements. One case is not universal and repeated copies are not independent evidence. Put reusable rules in references; retain private facts in the project/profile. Recheck the original failure and nearby successes, preserve the preceding release and paired semantics. Daily work loads current state and relevant rules, not the whole feedback archive. No automatic feedback transmission, weight training, background observer or instruction rewriting is introduced.
