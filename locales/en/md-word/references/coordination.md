# Executors and handoff

The main agent owns requirements, agreed decisions, deliverables, and coherent explanation. It, another agent, a person, or several executors may perform the core. Human-step-workflow authors/executes exact readable steps, including non-code actions. Treat old precise-code-workflow mentions as the predecessor's historical name, not a demand to restore old files.

Send a bounded assignment with the [template](../../../../shared/templates/en/handoff.md): specification/clauses, starting revision/state, dependencies, exact actions, adaptation limits, checks, return method. Tell a bounded executor which report materials to return; the full report skill is unnecessary. Prefer the English human-step edition when available, without loading both editions for one assignment.

A parent-directory instruction is not proof another agent received it. Provide accessible paths/links. Across machines/services, establish transfer; cloud subagents do not automatically access the user's local computer.

## Return evidence

- Done, already done, blocked, and remaining steps.
- Actual files, versions/commit, material deviations.
- Concise reasons for decisions and data transformations.
- Checks, inputs, actual results, limits.
- Required screenshots/intermediate results and provenance.
- Defects, open issues, next step, own log link.

Separate action and check statuses. Do not turn an unverified executor statement into a personally observed report fact. Inspect accessible artifacts; attribute other runs to their source/version.

## History and continuation

If intermediate actions are required, include capture in the packet in advance. Without evidence, distinguish reconstruction from files, human/agent reports, new reproduction, and unrecoverable history. A new run shows current behavior; it does not prove the historical development sequence.

On chat handoff, provide current specification, artifact versions, completed work, checks, user decisions, limits, and next step. Update concise state and leave history in logs. Require neither full prior chat nor hidden reasoning.

For built-in delegation see [subagents.md](subagents.md). It is one execution option, not mandatory architecture.
