# Paired editions and economical loading

Select one instruction edition only from an explicit instruction-language setting in the task, then an explicitly selected profile; otherwise use English, including for Russian requests. A requested output/log language is not an instruction-edition setting. Choose output and log language independently. Keep commands, names, UI labels, literal evidence and source bytes intact. Maintain one event log, not translated duplicates. Comment/commit/report style is a task/profile choice, not a private author's default.

During authorized development update both editions' semantics together. Record source revision, paired files, intentional localization differences and semantic checks outside runtime resources. Propagate behavioral fixes and checks to both; wording-only localization does not establish a new capability. Load references only for the actual role/topic.

For requested archive delivery use relative paths, permitted contents and one local archive validation; preserve prior checkpoints. Inspect actual remote-write results when remote edits are assigned. ZIP creation does not establish installation or acceptance. Follow the selected destination and permissions.

Measure token savings only using a named tokenizer on the actual loaded files. Separate entrypoint, optional references, evidence and session traffic. Tokenizer, caching, outputs and resource selection affect cost; promise no universal percentage or historical savings without usage measurements.

Private catalog quote/header compatibility is documented in [ratings](ratings-and-cases.md). Public adapted summaries are separately labeled review drafts, never translated “original quotes”. Keep task-specific style/scale outside universal instructions. New runtime prose supports both languages while some legacy diagnostics remain Russian; complete host localization has not been tested.
