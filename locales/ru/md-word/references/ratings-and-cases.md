# Оценки, происхождение и формы кейсов

Разделять приемку, оценку пользователя, оценку преподавателя и наблюдения качества. Записывать значение/точность, отображение, автора, область, исходную шкалу, дату/дату сообщения и свидетельство. Различать прямой ответ преподавателя и число, переданное пользователем. Одобрение черновика не является сдачей; прежняя приемка не удостоверяет очищенные производные или изменяемые текущие файлы. Неизвестное — null, а не ноль.

Сохранять реальную шкалу и историю уточнений. Записанная относительная шкала может иметь базу 1, предпочтение больших значений и незаданные границы; это не процент, вероятность или универсальная учебная шкала. Не нормализовать значения выше 1, не усреднять разные мнения/шкалы и не выдумывать причины/коэффициенты. Примеры выбирать по требованиям/данным/доказательствам/оформлению до баллов. Кейс до выпуска не проверяет эффективность позднего скила.

[Адаптированные исторические кейсы](../examples/index.md) и [структурированный вариант](../../../../shared/examples/historical-candidates.json) — проекты для просмотра, а не новый утвержденный runtime-каталог. В них точный пересказ, исключены идентификаторы/цитаты/ссылки и некоторые даты. Скрытая известная дата отличается от неизвестной в источнике. Приватные оригиналы неизменны. Независимая синтетика парсеров не является перенесенными сдачами. Не выдумывать исходную цитату ради прохождения прежнего валидатора адаптированным пересказом.

Для явно выбранного приватного рабочего каталога `case_catalog.py` сохраняет schema 1/2. Для уточненных авторства/шкал использовать schema 2; десятичные значения — строки, отображение согласовано. Schema 2 хранит реальную quote/source, scope, rater, date либо reported_date; преподавательский source — `teacher_reported_by_user` с source_ref. Неизвестный scale_id допускает null; проверять лишь явные границы. Приемка требует реального подтверждения пользователя. Текущий каталог обновлять под прежним ID после проверки свежести; завершение задачи не переписывает установленные снимки.

Помощник принимает следующие точные русские заголовки (либо их английские эквиваленты) в шапке кейса:

```text
Текущая оценка отчета пользователем: **VALUE**
Оценка преподавателя со слов пользователя: **VALUE**
```

Использовать `python3 <package-root>/shared/scripts/case_catalog.py validate <private-catalog>/ratings.json`, затем `index <private-catalog>/ratings.json --language ru --out <private-catalog>/index.md`. Условные пути заменить выбранными. Индекс использует только реально полученные case URL; локальный case_file остается относительным. Проверка подтверждает согласованность, а не реальную приемку/качество. При недоступности каталога оставить явно несинхронизированную запись задачи, а не конкурирующий основной реестр.
